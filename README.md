# ☕ نظام زام للعمليات (ZAM Operations System)

نسخة موحّدة ومُصلحة من نظام إدارة عمليات مقهى "زام"، مبنية من دمج كل الشاشات المتاحة (20 شاشة من ملف Stitch + الشاشات الأصلية على GitHub) في مشروع واحد شغّال بروابط سليمة واتصال حقيقي بـ Supabase.

## 🗂️ بنية المشروع

```
/
├── index.html                  → شاشة الدخول (متصلة فعلياً بـ Supabase)
├── register/index.html         → تسجيل موظف جديد لأول مرة
├── dashboard/index.html        → لوحة التحكم الرئيسية
├── branches-checklists/        → إدارة الفروع وتشيك ليست البار
├── staff-management/index.html → إدارة الطاقم (متصلة بقائمة موظفين حقيقية)
├── daily-report/index.html     → التقارير اليومية والمبيعات
├── reports-monitor/index.html  → متابعة تقارير المشرفين
├── reports-log/index.html      → سجل التقارير ومعرض التوثيق
├── supervisor-checklist/       → قائمة مهام المشرف (متصلة فعلياً - قراءة وتحديث حي)
├── automation-settings/index.html → إعدادات التنبيهات والأتمتة
├── employee-profile/index.html → الملف الشخصي للموظف
├── assets/supabase-config.js   → إعدادات الاتصال + دوال API مشتركة لكل الشاشات
└── schema.sql                  → مخطط قاعدة البيانات الكامل (نفّذه في Supabase أولاً)
```

## ✅ الحالة الحالية (بصراحة تامة)

| الشاشة | الحالة |
|---|---|
| تسجيل الدخول | ✅ متصلة فعلياً — تتحقق من `profiles.passcode` الحقيقي في Supabase |
| تسجيل موظف جديد | ✅ متصلة فعلياً — تحفظ بيانات حقيقية بحالة `pending` |
| قائمة تحقق المشرف | ✅ متصلة فعلياً — تقرأ وتحدّث المهام حياً في قاعدة البيانات |
| إدارة الطاقم | ✅ الجدول يعرض الموظفين الحقيقيين من قاعدة البيانات (القراءة فقط حالياً) |
| باقي الشاشات (8) | ⚠️ الروابط والتنقل بينها **مُصلحة بالكامل** وتحمّل اتصال Supabase وتتحقق من تسجيل الدخول، لكن البيانات المعروضة فيها (الرسوم البيانية، الجداول، الإحصائيات) **لسه ثابتة (mock)** ومحتاجة ربط إضافي بنفس أسلوب الشاشتين السابقتين |

## 🚀 خطوات النشر

### 1. قاعدة البيانات (لازم أولاً)
افتح مشروعك على Supabase → SQL Editor → الصق محتوى `schema.sql` بالكامل ونفّذه. هيبني كل الجداول + سياسات RLS الأساسية + مستخدم مدير تجريبي برمز `1234`.

**⚠️ غيّر رمز الـ 1234 فوراً بعد أول دخول**، وراجع سياسات RLS في `schema.sql` قبل الإطلاق الفعلي للعملاء — السياسات الحالية مبسطة للبدء فقط.

### 2. النشر على Netlify
أسهل طريقة: ارفع مجلد المشروع كامل مباشرة على Netlify (Sites → Add new site → Deploy manually / Drag & drop)، أو ادفعه لمستودع GitHub الحالي (استبدال الملفات القديمة) إذا كان متصل بـ Netlify فعلاً لنشر تلقائي.
